# 真实对话人工内容审阅（2026-09-16）

审阅对象：同目录 `conversation-agent.json` 的最终 16 轮定向测试。执行模型 Qwen3-4B-Instruct-2507，NF4 double quantization，生成 seed 20260916。这里的“人工审阅”指本次工程交付中逐条检查实际文本，不是医学专家评审。

## 已观察到的改善

- 用户不会描述以及随后说 What? 时，回复围绕如何表达展开，没有输出“The user feels…”这类旁白。
- Whats cold 的回复列出了身体感觉冷与感冒两种可能含义。用户接着澄清后，回复跟随了新的含义。
- 知识提问、他人的症状与范围外请求没有写入本人症状记录。
- Drowsiness 的 present → absent 更正保存在记录中，后续查询能够读出正确状态。
- 旅行请求得到范围提示；应用操作问题提到了真实的症状状态下拉框。

## 尚未达到的质量要求

- 连续 yes 的两条回复虽然不再回到原始意图分类失败菜单，但仍在以相似方式请求用户提供细节。没有问号不等于语义上已经充分推动了对话。因此自动检查中的该项只标注为语法检查。
- 用户只问知识时，回答仍可能追加不必要的症状追问。后续含义澄清也可能被扩展为症状采访。
- 个别医学解释过度简化；本次没有逐条做医学事实评估，不能把通过测试当作医学准确性证明。
- 应用帮助偶尔会用笼统的“edit option”措辞，虽然也提到了真实下拉框；这还不够精确。
- 相同本地模型的审校仍可能保留草稿中的问题，不能当成独立可信验证器。

## 结论与使用范围

工程回归、状态隔离和定向自动检查通过；总体自由对话质量仍需改进，不能声称“完全理解用户意图”或“语义质量全部验收通过”。当前可作为有运行证据的课程原型和对话工程案例，展示开放式分析、上下文、受校验记录、评估与失败诊断。

下一次模型或提示词迭代应保留这些对话，并加入未见表达、长对话与混合请求，由内容审阅检查是否真正推进对话。不要只增加同义正则或只统计接口成功率。
