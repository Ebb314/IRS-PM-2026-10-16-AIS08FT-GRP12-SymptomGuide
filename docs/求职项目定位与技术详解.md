# 求职项目定位与技术详解

## 一句话定位

面向 AI Development / Applied AI Intern 的医疗对话应用工程项目：负责把自由文本转换为可追溯的症状证据，维护可纠正的多轮状态，并将团队算法封装成可独立测试的前后端应用。

项目名称建议：**Symptom Guide — Medical Dialogue Engineering Prototype**。
副标题：**NLP, Stateful Dialogue & Full-stack Integration**。

这是学术项目。当前只确认用户承担 NLP、chatbot 和前后端；学历、工作经历、在新加坡的工作资格、可实习时间与其他技能未提供，不补写。实现由本轮 AI 协助扩展现有 demo，提交简历前需要用户完成代码审阅、复跑与面试口述验证。

## 架构与个人边界

浏览器的自然语言消息经 FastAPI 校验后进入 NLP，输出具有标准 ID、状态、原文来源的证据。编排层将证据写入结构化会话，再调用队友提供的召回与搜索接口，最终将下一问题或候选结果交给 Vue 呈现。SQLite 保存状态与请求重放结果，使刷新恢复和异常重试有明确语义。

个人负责：词表接口、自然语言处理、会话编排、持久化、HTTP 适配、前端、测试与文档。
团队依赖：真实召回训练、排名模型、信息增益或其他搜索启发式、KG 构建与医学关系质量。
共同确定：疾病和症状映射、非二元证据、停止策略、结果展示口径。
本版本没有用 mock 冒充队友模型，也没有把图谱构建或搜索算法归为用户个人成果。

## 五个可以展开的技术亮点

### 1. 从关键词匹配到有来源的证据建模

原始输入是字符串，召回模块需要结构化数据。直接提取关键词会把“没有发热”当作发热，也难以处理父母的症状和用户纠正。实现将标准概念、断言状态、主体、时间类别和原文区间一起保存。否定不是删除关键词，而是保留有方向的证据；未知也不是阴性。前端能够显示抽取内容并允许确认。

关键取舍：默认十个标准概念，牺牲覆盖广度换取独立运行与可审查的语义。真实医学词表需重新映射和评估。duration、severity、多选值没有实现，不能在面试中暗示已经支持完整病史理解。

### 2. 对话状态与语言模型职责分离

系统保存结构化状态，而非每轮把历史文本重新拼接后从零诊断。每轮只更新增量证据，用户纠正可以替换当前状态并留下历史记录。已有问题的 yes/no/unknown 按当前标准 ID 绑定；不确定的症状不进入阴性列表，并进入避免重复询问的集合。

可选 LLM 接口只能产生抽取结果，疾病与问题仍由确定接口返回。即使生成模型不可用，默认版本也可以继续使用规则处理。这能展示“如何控制模型输出进入业务状态”的工程判断。

### 3. 事务、幂等和乐观并发

网络断开时，前端无法知道请求是否已经成功。为了避免重复点击或重试多记录一轮，前端保存原请求，服务端存储请求指纹与成功响应。同一请求 ID、同一请求体直接重放；同一 ID 不同内容拒绝。

版本控制解决另一类问题：两个不同请求都基于旧状态修改。事务内检查版本，只有一个请求可以成功。SQLite 在同一事务中写入会话和重放记录，失败时整体回滚。数据库返回独立对象，避免引用共享导致状态被无意修改。

取舍：本地锁和 SQLite 写事务覆盖整个编排，会在等待外部模型时阻塞其他写入。它适合单机学术 demo，不能宣称高并发架构。若真实上线，再考虑按会话串行队列、外部调用后的版本提交和生产数据库。

### 4. 缺少队友模块仍能测试的适配边界

定义召回、下一问题和药物关系三个接口，提供 deterministic fixture 与 HTTP 两种实现。前后端不依赖具体算法。默认 fixture 使用独立命名空间；真实接入使用配置切换，不改页面 API。

对远程返回执行类型和业务检查，覆盖超时、HTTP 错误、非法 JSON、越界分数、无效问题与不属于当前证据的引用。remote 失败返回 503，不静默混入 mock。这样能明确回答“你如何在跨团队依赖未完成时交付自己的部分”。

### 5. 分层评估与可核验结果

后端自动测试、人工编写 NLP 回归集和真实浏览器检查分别验证不同问题。NLP 指标按“概念 + 断言状态”计算；浏览器测试验证按钮、真实请求、刷新恢复、错误重试和下载。所有结果均保存在仓库。

54 个 NLP 样例在开发期间参与了规则修正，不能称作 held-out。默认 mock 的分数与问题顺序不能用于诊断准确率、问诊轮数改进或临床效率宣传。当前没有真实用户数、真实诊断收益或云端生产运行数据。

## 90 秒英文项目介绍

I worked on the NLP, dialogue management and full-stack integration of an academic medical chatbot. My teammates were responsible for disease retrieval and informed search, so I designed interfaces that let me develop and test my part independently.

The main challenge was converting free-text symptoms into reliable inputs for those algorithms. I represented each symptom with a canonical identifier, an assertion status and its source text. That let the application distinguish negative and uncertain answers, preserve corrections, and show users what the system had understood.

I also added persistent sessions, version checks and idempotent request handling. If a request fails or the page is refreshed, the application can recover its state without recording the same update twice. I tested the backend and the real browser workflow using clearly labelled algorithm fixtures.

The project demonstrates application engineering and evaluation discipline. It is not clinically validated, and I do not claim my teammates' retrieval or search algorithms as my own work.

## 面试中最值得展示的五分钟 Demo

第一分钟：说明三人分工，指出 mock 提示与有限词表。
第二分钟：输入否定句，观察标准化证据；回答 unknown，解释与 absent 的区别。
第三分钟：纠正一项证据并刷新页面，解释服务端状态与持久化。
第四分钟：展示测试中的失败回滚、版本冲突与幂等重试代码。
第五分钟：展示 evaluation/REPORT.md，解释为什么完美回归结果不等于泛化能力，以及接入队友后下一步如何评估。
