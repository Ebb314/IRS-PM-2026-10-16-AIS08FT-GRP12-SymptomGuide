# 队友接入契约 v1

## 责任边界

本模块负责文本理解、会话状态、前后端与调用编排。召回排序、知识图谱构建、搜索启发式由队友负责。默认 mock 的候选数量根据证据数量变化，问题为固定顺序，只证明流程可运行。绝不把 mock 的排名或分数用于疾病准确率报告。

原工程的 P001 等 ID 与后续导入的 KG 文件发生语义冲突。新 mock 全部使用 DEMO: 命名空间。接入真实数据前，必须共同确定稳定概念 ID、名称、别名、类型与映射表。禁止用行号重新编号后继续复用旧 ID。

## 前端 HTTP API

| 方法 | URL | 用途 |
|---|---|---|
| POST | /api/chat/start | 首条自由文本，支持重复请求重放 |
| POST | /api/chat/message | 同一会话自由文本续聊或纠正 |
| POST | /api/chat/answer | 当前问题的 yes/no/unknown |
| POST | /api/chat/correct | 显式修正已有证据 |
| GET | /api/chat/session/{session_id} | 恢复完整会话 |
| DELETE | /api/chat/session/{session_id} | 删除会话及重放记录 |
| GET | /api/vocabulary | 当前支持的标准症状 |
| GET | /api/health | 实际配置模式、NLP 引擎和词表大小 |

start 请求：
```json
{"message":"I am coughing, but no fever.","request_id":"unique-start-0001"}
```

后续 message 请求：
```json
{"session_id":"服务器返回值","expected_version":1,"request_id":"unique-message-0002","message":"Actually I do have fever."}
```

answer 请求还需要：
```json
{"session_id":"服务器返回值","expected_version":1,"request_id":"unique-answer-0002","answer":"unknown","symptom":{"kg_id":"DEMO:breathlessness","kg_name":"shortness of breath"}}
```

correct 请求使用 kg_id 与 status；status 为 present / absent / uncertain。服务端只允许纠正当前已存在的证据，且使用服务端标准名称。

200：成功。422：schema、空白文本、超长文本或非法枚举。404：会话不存在。409：版本过期、错误问题、重用 request_id 但内容不同、会话达到 100 次版本上限。503：队友接口超时、异常或违反契约。失败事务不写入半成品证据。

response 包含 version、messages、evidence、evidence_history、excluded_evidence、positive_symptoms、negative_symptoms、uncertain_symptoms、next_symptom、candidate_diseases、stop_reason、timings_ms 和 mode。request_id 的重试必须使用完全相同的 URL 与请求体，包括旧 expected_version；服务端先查重放，再检查版本。

## 接入队友的 HTTP 服务

设置：
```powershell
$env:REASONING_MODE="remote"
$env:TEAMMATE_API_URL="http://127.0.0.1:8010"
$env:KG_NODE_FILE="E:\path\to\agreed_symptoms.csv"
```

三个端点是同一服务下的独立接口。也可以直接实现 services/interfaces.py 中的抽象类，在 dependencies.py 注入实例。

### POST /recall

输入：
```json
{"positive":[{"kg_id":"DEMO:cough","kg_name":"cough"}],"negative":[{"kg_id":"DEMO:fever","kg_name":"fever"}]}
```

输出为数组：
```json
[{"id":"DISEASE:example","name":"Example candidate","score":0.62,"evidence_ids":["DEMO:cough"],"source":"teammate-recall-v1"}]
```

必须发送完整累计状态。unknown 不进入 positive 或 negative。返回分数按当前契约要求为 0..1 的排序分数，不能直接称为概率。evidence_ids 必须来自本轮输入的已确定证据；具体证据支持或反对的方向要在后续契约版本中扩展，当前前端只称“returned evidence”。

### POST /search

输入包含 candidates、positive、negative、asked_symptom_ids，后三者保留相同 schema。asked_symptom_ids 包括已回答和不确定症状，以防重复询问。

输出：
```json
{"kg_id":"DEMO:chest_pain","kg_name":"chest pain","heuristic_score":0.73,"rationale":"Explanation supplied by the search module."}
```

没有可询问问题时返回 JSON null。禁止返回已解决、已问过或词表外的 ID。服务端以本地词表名称为准。

### POST /drug-relations

输入包含 candidates。返回数组，每项包含 name、related_disease、relation、source、note。暂时不实现时返回 [] 即可。只展示可追溯的关系类型与来源，不输出用药方案。默认 mock 返回空数组。

## 停止策略

当前顺序：空候选 → 达到五轮上限 → 候选数不超过二 → 否则选择问题；无问题时停止。所有停止条件均有 stop_reason。只有 candidate_threshold 调用药物关系接口。队友若固定返回 Top-K，必须先约定如何产生真正可缩小的候选集合，否则候选数量阈值没有意义。

最大轮数计数包含自由文本更新和按钮回答；显式纠正不重置已用预算，完整会话可以更新证据但不会无限扩展问答轮数。所有接口还受 100 个成功版本的会话上限约束。

## DDXPlus 和 PrimeKG 的后续接入

本次没有下载或训练队友模型，也没有擅自映射两个数据集。当前协议只覆盖有限二元症状状态。DDXPlus 的类别、多选字段需要共同设计 value 与 question_type，并同步 UI 和测试；不能把类别值当二元症状硬塞入本协议。建议建立独立 mapping.csv，记录 canonical_id、dataset_id、kg_id、mapping_method、review_status。未映射项保持缺失，不根据字符串相似度自动确认医学等价性。

## 2026-09-15 AI 升级接口补充

现有 mutation 请求体保持兼容。响应增加：

- evidence[].duration_text / severity_text：用户原文槽位，可为空；未做标准时间或严重程度编码。
- ai_trace：最近一次请求的 intent、nlu / generation、retrieval、citations、validation / fallback_reason。
- model_call：model、device、input_tokens、output_tokens、latency_ms。latency_ms 是生成阶段时间，不是整个 HTTP 延迟。
- health 增加 ai_profile 与 generator；local 表示实际本地模型加载路径，mock 仅描述疾病算法适配器。

知识问答、解释与总结写入消息历史并增加 version，不修改 evidence、round 或 pending question。trace 是观测信息，不应当作为客户端业务状态判断的唯一依据。字段详细例子见 evaluation/browser-ai-report.json。

local 模型默认先加载本地 Qwen + MiniLM；初始化失败时请求失败，不会伪称模型可用。运行中结构化输出或回答校验失败则返回可见规则 / 原文回退。队友 remote 适配器错误仍按旧契约处理，不能静默伪装为 mock 结果。

## 2026-10 KG 推理模式补充

- 新增 `REASONING_MODE=kg`：在进程内直接实现三个抽象接口（`services/kg_reasoning_service.py`），不需要另起 HTTP 服务。`remote` 模式与本契约其余部分保持不变。
- `DiseaseCandidate.id` 使用 `PRIMEKG:<node_index>`，`source` 为 `primekg-kg-recall-v1`；`evidence_ids` 为候选疾病所匹配的 positive 症状 ID。
- 召回接收的 negative 症状为硬过滤：关联任一 negative 症状的疾病不会出现在候选中；KG 标注为"不具有"某个 positive 症状的疾病同样会被排除。
- `NextSymptom.heuristic_score` 取值 0–0.5（加权平衡切分），`rationale` 说明该症状如何切分当前候选。
- `DrugRecommendation.relation` 为 `indication` 或 `off-label use`，`source` 为 `PrimeKG project KG`；对任一剩余候选有禁忌的药物会被排除。
- kg 模式下 `MAX_ROUNDS` 默认 12，其他模式仍为 5；可用环境变量 `MAX_ROUNDS` 覆盖。依据见 [KG推理集成记录](KG推理集成记录.md)。
