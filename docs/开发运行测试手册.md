# 开发、编写、运行与测试手册

## 1. 交付对象与现有工程变化

实际原工程路径为 E:\Study\StudyAtNUS\GC1_Project，并非最初消息中的 GC1\_Project。保留 Vue 3、TypeScript、Pinia、Element Plus、Axios、Vite 和 FastAPI。原始 KG CSV 保留，未改写队友的数据，也未训练队友算法。

原 demo 的具体问题：
1. mock 中 P001 是 fever，实际 kg_nodes.csv 中 P001 是 Growth abnormality，ID 与语义不一致。
2. NLP 默认只匹配标准名称；上下文窗口中的否定词可能污染另一个分句。
3. 无法表达“不确定”，只有 yes/no，未知容易被当成阴性。
4. 未匹配文本后的继续输入会重新 start，丢失会话连续性。
5. 缺少自由文本续聊和历史证据纠正。
6. 内存 get 返回同一对象，读改写并非完整原子事务，无法重启恢复。
7. 前端将 score 转成百分比进度条，容易让人误以为患病概率。
8. mock 返回虚构药物文本，缺少明确的关系语义。

当前实现将这些问题分别落在数据命名空间、NLP 断言处理、状态机、SQLite 事务和前端证据确认中。

## 5. 编写与阅读顺序

### 第一步：定义证据与请求

backend/app/models/chat_models.py：
- Symptom 是标准 ID 和名称。
- ExtractedSymptom 增加状态、主体、时间类别、文本区间、轮次与来源。
- 不确定状态与“尚未问过”不同，后者是没有对应已知证据。
- StartChatRequest 用于新会话；后续变更必须携带版本和请求 ID。
- SessionState 是当前状态，evidence_history 是历史证据事件。
- ChatResponse 返回同一份状态和下一问题，前端不独立推导医学状态。

本版是有限二元症状抽取；持续时间数值、严重度、DDXPlus 类别与多选值没有实现结构化字段，不应写成已经支持。

### 第二步：实现自然语言处理

backend/app/services/nlp_service.py：
1. 读取标准词和别名，拒绝重复 ID。
2. 构造长词优先、有词边界的匹配。
3. 找出每个文本片段与所在分句。
4. 分别判断否定、不确定、其他人和历史信息。
5. 其他人或历史信息保留到 excluded，不参与当前症状召回。
6. 同一句中的冲突转成 uncertain，明确纠正则采用后出现的信息。
7. 记录原文起止位置，便于前端核对。
8. 未匹配表达产生提示，不自动当作症状不存在。

这是有边界的英语规则方案。复杂否定、隐喻、条件句和跨句指代不保证正确。最终评估使用开发期人工编写的语句，不能推断真实患者数据上的效果。

### 第三步：实现状态更新与事务

backend/app/services/chatbot_service.py：
- start/message/answer/correct 统一进入 _execute。
- 先在事务内查询 request_id 的历史响应。
- 相同请求直接返回原响应，不再次增加轮次。
- 同一 request_id 不同内容拒绝。
- expected_version 必须与数据库版本一致。
- NLP 成功后合并证据，再调用队友模块。
- 队友调用失败则抛出异常，事务整体回滚。
- 成功后保存新状态和重放响应，一起提交。

跨轮次反向描述如果没有明确纠正词，会先设为 uncertain；用户可在证据面板明确确认。显式按钮回答只绑定当前问题，服务端不信任客户端传来的标准名称。

### 第四步：隔离队友算法

interfaces.py 保留抽象契约，mock_reasoning_service.py 提供可预测的固定场景，remote_adapters.py 使用 HTTP 替换。backend/app/dependencies.py 根据 REASONING_MODE 注入实现。

mock 模式使用独立 DEMO: ID；remote 模式不自动回退到 mock。异常会返回 503，以免向用户呈现看起来正常但实际是模拟的数据。

### 第五步：前端状态与恢复

frontend/src/stores/chat.ts：
- 服务端 response 是事实来源。
- pending 保存尚未完成的请求，重试时保留同一 request_id 和版本。
- 成功后用服务端完整 messages 更新聊天记录。
- sessionStorage 只保存会话 ID，刷新后从后端恢复。
- 显式纠正使用 /correct；自由文本继续使用 /message。
- 删除操作同时删除服务端会话；“Start new local view”仅重置浏览器视图，不删除未知后端记录。
- 导出生成当前响应 JSON，含用于复盘的证据与耗时。

SQLite 持久化到 backend/runtime/sessions.sqlite3。这个本地学术原型没有账号权限体系、自动过期或生产级高并发设计，只应用虚构输入。不要把数据库或会话导出内容公开提交到仓库。

## 7. 手工演示流程

1. 输入 “I am coughing, but no fever.”
2. 检查 cough=Present、fever=Absent，原文词片段可核对。
3. 对呼吸困难追问选择 Not sure，确认没有被放进 Absent。
4. 继续回答后续问题，查看明确标注的 fixture candidates。
5. 将 fever 下拉框改为 Present，观察版本、证据历史和候选结果重新计算。
6. 输入 “Actually no fever. I have a headache.”
7. 刷新页面，确认消息和证据恢复。
8. 展开 Developer trace，检查来源、轮次和模块耗时。
9. 导出 JSON，再删除会话，确认服务器已删除状态。

讲解时把固定 mock 问题顺序明确称为“用于联调的模拟策略”，不能称为个人实现的信息增益算法。

## 8. 可选模型路径

### 本地 Ollama 结构化抽取

实现遵循 Ollama /api/chat 与 JSON schema 接口：
https://docs.ollama.com/api/chat
https://docs.ollama.com/capabilities/structured-outputs

先自行安装 Ollama 并下载一个适合本机资源的模型，使用 ollama list 确认实际模型名，然后：
```powershell
$env:NLP_ENGINE="ollama"
$env:OLLAMA_MODEL="填写本机已安装的模型名"
$env:OLLAMA_URL="http://127.0.0.1:11434"
powershell -ExecutionPolicy Bypass -File scripts/run.ps1
```

模型只抽取有限词表中的结构化证据，不能决定疾病、问题或药物。代码检查 schema、ID、唯一原文引用与重复概念。8 秒 HTTP 超时或非法输出会可见地回退到规则，并在 response.nlp_engine 与 warnings 中标明。格式校验不能证明语义正确，仍需要独立评估。

本次验证的是模拟 HTTP 输出的适配器及回退，不是某个真实 LLM 的推理质量。未下载大模型，未产生付费 API 调用。默认评估脚本强制使用 rules-v2，不会把回退误算为模型成绩。

### 原工程生物医学 Transformer 路径

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-nlp.txt
$env:NLP_ENGINE="rules"
$env:NLP_USE_TRANSFORMERS="true"
powershell -ExecutionPolicy Bypass -File scripts/run.ps1
```

NER 使用原工程的 d4data/biomedical-ner-all，语义映射使用 all-MiniLM-L6-v2。新增了最低相似度与前两名分差判断，但阈值没有在临床数据上调优。模型下载、首次加载、显存/内存和真实效果未在本次验收中验证。不要同时开两个模型路径来增加不必要的资源占用。

## 9. 常见问题

- 找不到模块：确认使用根目录 .venv/Scripts/python.exe，而不是系统另一个 Python。
- 页面 404：先构建 frontend，再重启后端；挂载静态目录发生在启动时。
- 端口被占用：停止旧服务或用 run.ps1 -Port 8001。
- 409：前端读取旧版本或错误的当前问题；Reload session 后重新操作。不要直接修改数据库版本。
- 503：队友服务未启动、超时或格式不符；修复服务后使用 Retry same request。
- 没抽取到症状：打开 Supported vocabulary，确认有限词表与别名覆盖，或增加经过审查的词表条目及测试。
- mock 模式更换大型 CSV 后启动失败：这是防止 ID 混用的主动检查；真实词表应与 remote 模式一起使用。
- 浏览器缺少 Chrome：设置 BROWSER_CHANNEL=msedge；也可调整脚本使用安装好的 Playwright Chromium。
- 构建显示体积提示：继承的 Element Plus 全量引入造成较大 bundle；本地 demo 已可运行，未宣称首屏性能优化。
- 后端测试有依赖弃用警告：本次所用 FastAPI/Starlette 对测试客户端的兼容提醒；不代表测试失败。迁移依赖时重新跑全部测试。
