# 连续对话上下文修复记录（2026-09-16）

## 问题与修复范围

用户提供的五轮连续对话暴露出：此前测试只检查意图标签和状态，无法证明回复有帮助。系统把表达困难当作症状报告/摘要，把“What?”当作独立问题，且缺少上一轮回复作为上下文。测试通过不等于对话质量已经解决。

本次在现有 LLM 路由之上增加三个对话动作：guide（帮助描述）、repair（重新解释）、clarify_term（词义澄清）。明确的表达困难与短句困惑由对话规则约束分流，LLM 仍负责生成回应；trace 同时保存模型初次判断和 explicit-conversation-cue 策略，不能把规则结果冒称为模型识别正确。

## 实现

- `conversation_context.py`：HTML 实体、空白、Whats/What's、dont 归一化；识别表达困难与困惑信号；抽取最近四条历史消息；检测第三人称转述与占位符。
- `DialogueAI.classify`：完成 LLM 判断后处理明确对话信号。`knowledge_target` 和问答入口使用归一化文本，原始聊天消息仍保留。
- `IntentService.support`：使用近期对话及当前输入，引导用户用普通语言描述；一次问一个问题；困惑时重新解释；cold 先区分 common cold 与 feeling cold/chilly。
- `ChatbotService`：local 模式的症状输入没有提取到可靠证据时，转入描述引导，保留已记录证据、最近症状主题及待回答问题。
- 通用对话输出遇到“The user feels…”或“The question…has been asked”等元叙述会被拒绝。引导输出不符合格式或词义澄清缺少必要选项时，使用明确的回退问题，并保留真实失败模式。

本次没有改召回、搜索和候选疾病接口，也没有重新构建前端；页面使用现有消息和 trace 组件。

## 实测结果

使用现有本地 Qwen2.5-1.5B-Instruct / CUDA。127 项后端测试通过。`test-conversation.cjs` 使用两组各五轮的连续会话，包括用户原句和口语改写，检查：

1. 是否进入正确对话动作。
2. 是否出现第三人称转述。
3. 引导/澄清是否包含一个可回答的问题。
4. cold 是否同时给出感冒和感觉冷两个意义。
5. 这些非报告消息是否保持证据、追问轮数、待回答症状不变。

暂存工程真实测试的部分输出：

| 输入 | 实际回复 | 来源 |
|---|---|---|
| How to describe? | It's okay to start by describing how you're feeling. What seems unusual or different for you? | LLM |
| I feel bad but i dont know how to say | That's understandable. Start by telling me what specifically feels off or different for you? | LLM |
| What? | Can you tell me about any unusual feelings or sensations you've been experiencing lately? | LLM，带前文 |
| Whats cold | Do you mean a common cold, or feeling cold or chilly? | 模型校验失败后的澄清回退 |

这十轮中，五轮为通过校验的 LLM 引导回复，三轮为引导/澄清回退，两轮 fever 知识回答为来源摘录回退。因此，10/10 表示测试所检查的行为通过，**不代表十轮都是成功生成，更不代表开放域对话正确率**。完整回复、路由、生成 token/耗时及回退模式保存在 `evaluation/conversation-context.json`。

## 仍存在的限制

目前是有限窗口上下文和明确对话信号的修复，不是完整对话规划器。cold 的词义澄清是明确覆盖的歧义案例，不代表系统能消解全部歧义词。小模型的自然表达、追问效果和长对话理解仍有限；后续需用独立收集的连续对话评估回应质量、重复追问、澄清完成率及事实准确性，不能继续仅靠标签命中率判断智能程度。
