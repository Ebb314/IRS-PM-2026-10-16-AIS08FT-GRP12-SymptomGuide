# 否定与不确定症状状态修复

日期：2026-09-17。项目：`E:\Study\StudyAtNUS\GC1_Project`。

## 复现与原因

用户原句：`I dont think i have a fever`。

修复前，真实模型的语境理解描述为“没有当前发热”，但最终 evidence 中 Fever 为 present，因此 Symptom log 显示到了错误分组。另有实际复现：

| 输入 | 修复前记录 | 预期 |
| --- | --- | --- |
| I dont think i have a fever | Fever: present | absent |
| I dont have Drowsiness. | Drowsiness: present | absent |
| Drowsiness is uncertain. | Drowsiness: present | uncertain |
| Drowsiness? I'm not sure. | 未记录 | uncertain |
| I have Drowsiness. → I don't have Drowsiness. | 从 present 变成 uncertain，回答却声称 absent | absent |

三个原因发生在模型理解之后：

1. `conversation_agent.py` 将“词表名称精确匹配”误用为“状态可信”，用规则解析器的 status 覆盖模型的 status。规则没有覆盖 `dont` 及部分后置不确定表达，默认 present，导致正确的语境理解被覆盖。
2. `chatbot_service.py` 对跨轮状态变更使用固定的 actually / correction / now 等关键词判断。即使最新句子明确否定，只要没有这些词，也强制改成 uncertain，造成 accepted trace、最终记录和自然语言回答不一致。
3. 所有包含问号的文本一律禁止写入，连 `Drowsiness? I'm not sure.` 这类明确表达不确定的说法也被拒绝。

## 修改

- 精确词表匹配只验证概念身份，不再覆盖语义状态。通过原有候选 ID、原文引用、主体、时态和问句校验后，保留 LLM 提议的 present / absent / uncertain。
- LLM 理解提示明确要求保留否定和不确定的症状，每个症状独立判断；`dont` 和否定信念属于自然语言理解范围，不以匹配某个关键词作为对话意图分类。
- agent 路径采用最新已校验的当前症状陈述更新状态，不再要求额外的“更正暗号”。原状态保留在 evidence_history；不确定陈述仍保存 uncertain。
- 对明确的个人不确定表达及“症状名？我不确定”形式放宽问号限制，保留知识问题、其他人和历史提及的写入防护。
- 追踪增加 `understanding.proposed`，可以对照模型提议、校验后的 accepted 和实际 evidence，便于定位模型与程序之间的偏差。
- 不增加模型调用次数，不改回固定意图分类，也不修改侧栏的数据来源。Absent 和 Not sure 继续分别由 absent 和 uncertain 状态驱动。

Absent 表示用户报告没有该症状，不是临床排除；`I dont think...` 在本项目中按用户的否定陈述记录。`I'm not sure whether...` 记录为 Not sure，且不加入阳性或阴性召回输入。

本次针对正在使用的 local + agent 路径。独立的 offline 规则基线保留用于比较，不应把它的指标称为 LLM 理解能力。

## 测试

后端 170 项测试通过，其中新增 18 项断言状态回归，涵盖用户原句、缺省撇号、后置不确定、问号表达、多症状不同状态、跨轮变更、历史记录、持久化、幂等回放及召回输入隔离。

真实模型验收报告：`evaluation/assertion-status-live.json`。脚本对每轮比较 evidence 的预期状态，并重新读取数据库会话，核对 positive / negative / uncertain 三组字段。使用独立测试会话，只删除自己创建的会话。

本次实测结果：本机 Qwen3-4B-Instruct-2507（4-bit）共 11 轮全部通过，报告 `complete=true`、`passed=true`、`count=11`。这些结果验证状态提取和保存，不等同于对自然语言回答质量的全面评分。

浏览器端另以 `I dont think i have a fever. I'm not sure whether I have Drowsiness.` 验证：Symptom log 显示 All statuses (2)、Present (0)、Absent (1)、Not sure (1)；Fever 出现在 Absent 分组，其 Change status 选中 Absent；Drowsiness 出现在 Not sure 分组，其 Change status 选中 Not sure。回复文字与侧栏保存结果一致。

## 使用与已有会话

刷新页面，在 Show symptoms 中选择 All statuses。重新发送原句后，Fever 应进入 Absent；发送 `I'm not sure whether I have a fever` 后应进入 Not sure。

不会根据旧聊天内容批量猜测、重写已经保存的症状状态。之前被错误保存为 Present 的条目，可以重新描述或使用 Change status 修正；新版本处理同一会话的最新否定陈述时也可直接更新。
